# BOSS 渠道可验证策略条目

- 状态：草稿 / 待验证
- 生成时间：2026-05-20
- 来源：用户已标记的 `boss-channel-tutorial-strategy-draft.md`
- 用途：作为后续每日全量分析任务的策略验证清单。每日任务只负责验证和标记证据状态，不自动把策略写入正式策略库。

## 1. 使用规则

### 1.1 状态枚举

- `待验证`：条目已定义，但还没有跑过足够数据。
- `验证中`：已经开始观察，但样本量或时间窗口还不够。
- `数据不足`：当前事实日志缺字段、样本太少或无法区分变量。
- `倾向支持`：数据方向支持假设，但还不够稳定，不进入决策。
- `倾向反证`：数据方向不支持假设，或出现明显反向信号。
- `已验证待决策`：达到验证口径，可以交给用户判断是否正式采纳。
- `已采纳`：用户确认后，才可进入正式策略文件。
- `暂不采纳`：用户看过证据后决定不落正式策略。
- `过期`：平台、账号权益、团队流程或市场环境变化后不再适用。

### 1.2 每日全量分析任务口径

每天的全量分析任务应读取本文所有 `待验证`、`验证中`、`数据不足`、`倾向支持`、`倾向反证`、`已验证待决策` 条目。分析原因时统一使用目标日前置滚动窗口，不用当日操作直接解释当日结果。

目标日优先取最近一个完整自然日；如果用户明确要求查看当天进行中数据，当天只作为结果观察和后续窗口输入，不作为同日因果证据。

每条策略默认按以下窗口输出：

1. 当日结果窗口：只描述目标日或进行中当天的结果变化，不做同日因果判断。
2. 前 3 天原因窗口：回看目标日前 3 个完整自然日的操作结构、后段反馈和异常变量。
3. 前 7 天趋势窗口：回看目标日前 7 个完整自然日，判断短期趋势、延迟反馈和恢复/恶化路径。
4. 前 14 天基线窗口：回看目标日前 14 个完整自然日，判断当前结果相对基线是否异常。

每日任务输出每条策略时至少包含：

- 条目编号
- 当前状态
- 目标日
- 当日结果
- 前 3 天原因线索
- 前 7 天趋势
- 前 14 天基线
- 样本量
- 核心指标
- 对照组或基线
- 证据摘要
- 结论：数据不足 / 倾向支持 / 倾向反证 / 已验证待决策
- 是否建议改状态
- 需要用户决策的问题

每日任务不得输出候选人姓名、手机号、微信号、完整聊天原文、完整简历正文或完整 URL 参数。

### 1.3 标记规则

- 每日任务可以把条目标记到 `数据不足`、`验证中`、`倾向支持`、`倾向反证`、`已验证待决策`。
- 每日任务不能标记 `已采纳`，只能由用户决策后标记。
- 如果无法从当前事实日志验证，不要硬推结论，应标记 `数据不足` 并写明缺少什么事实字段。
- 如果某条策略同时影响多个方向，优先按用户标记归类验证，其他影响只作为辅助说明。

### 1.4 调整动作记录格式

如果某条策略触发了可尝试的调整动作，直接在该策略条目下追加 `调整动作记录`。动作记录只表示“建议试一下”或“已经试过”，不等于策略已采纳。

推荐格式：

```md
#### 调整动作记录

##### ACT-YYYYMMDD-ITEMID-001 动作标题

- 来源报告：`daily-full-analysis-YYYY-MM-DD.md`
- 执行状态：建议执行 / 已执行 / 执行中 / 待复盘 / 已复盘 / 已取消
- 触发信号：为什么提出这个动作。
- 建议动作：具体怎么调，尽量小范围、可回滚、可复盘。
- 不做事项：这次不要顺手做什么，避免变量混在一起。
- 执行记录：用户执行后补实际做法、账号、岗位、时间。
- 观察指标：执行后看哪些指标。
- 复盘窗口：观察多久后回看。
- 复盘结论：待填写。
```

用户执行后，可以直接把 `执行状态：建议执行` 改成 `执行状态：已执行`，并补充 `执行记录`。每日分析任务只负责继续观察动作后的指标变化，不自动把动作改成已执行或已采纳。

## 2. 底层认知验证条目

### BASE-001 BOSS 渠道应按完整漏斗复盘

- 用户标记：底层认知
- 状态：待验证
- 策略假设：只看打招呼数量不足以判断 BOSS 渠道效果，必须按“岗位曝光 -> 候选人看过/详情打开 -> 主动开聊 -> 候选人回复/聊天打开 -> 微信/电话/面试/入会”完整漏斗复盘。
- 可验证问题：每日是否能为账号、岗位、城市、招聘人员生成完整漏斗；是否存在某些阶段明显流失。

- 分析维度：日期、账号、岗位、城市、招聘人员、岗位类型。
- 判断标准：如果单看打招呼量与微信/后续结果相关性弱，而中间漏斗能解释流失，则标记 `已验证待决策`。
- 数据依赖：候选人曝光、详情打开、打招呼、聊天打开、聊天快照、微信采集、后续结果事件。
- 决策状态：未决。

## 3. 曝光专项验证条目

### EXP-001 职位内容与互动行为共同影响曝光

- 用户标记：曝光专项认知
- 状态：待验证
- 策略假设：职位内容和互动行为都影响 BOSS 对账号/岗位的曝光分发。
- 可验证问题：同一账号或同一岗位在内容调整、开聊/回聊/复聊变化后，曝光量和看过我的数据是否变化。
- 核心指标：候选人列表曝光、候选人卡片曝光、看过我的、详情打开、打招呼成功、聊天打开。
- 分析维度：岗位、账号、城市、日期、互动行为强度。
- 判断标准：若内容变化或互动行为变化后的曝光指标持续改善，并能排除明显节假日/流量波动，标记 `倾向支持` 或 `已验证待决策`。
- 数据依赖：职位内容版本、岗位城市、互动事件、曝光事件。
- 决策状态：未决。

### EXP-002 标题信息密度影响第一屏转化

- 用户标记：曝光专项认知
- 状态：待验证
- 策略假设：标题包含薪资、岗位类型、核心卖点时，比过短或信息少的标题有更高详情打开和招呼回复。

- 核心指标：曝光到详情打开率、打招呼到聊天打开率、微信采集率。
- 分析维度：标题长度、标题关键词、岗位类型、城市。
- 判断标准：如果 30 字以内且含核心卖点的标题稳定优于低信息标题，标记 `已验证待决策`。
- 数据依赖：岗位标题文本、曝光事件、详情打开、打招呼、聊天打开。
- 决策状态：未决。

### GOV-002 内部标签不能作为插件事实结论

- 用户标记：底层认知
- 状态：待验证
- 策略假设：“高潜力、待沟通、需进一步了解”等标签只能作为人工/分析侧复盘标签，不能进入插件端事实结论。
- 可验证问题：当前日志和策略文档是否存在把标签当作事实结论的情况。
- 核心指标：策略标签字段出现位置、插件事实事件字段、分析侧字段。
- 分析维度：文档、事实事件、后续分析字段。
- 判断标准：若只出现在策略或分析侧，标记 `已验证待决策`；若插件端编码结论，标记风险。
- 数据依赖：日志契约、事实事件样本、策略文档。
- 决策状态：未决。

### GOV-003 敏感与承诺表达需要可审计

- 数据依赖：岗位文本、聊天脱敏文本、政策口径。
- 决策状态：未决。

## 7. 每日全量分析任务模板

```text
任务目标：
读取 strategy/boss-channel-verifiable-strategy-items.md，针对所有未采纳且未过期的策略条目，生成今日全量验证报告。

时间窗口：
- 昨日自然日
- 近 7 日
- 近 30 日

分析要求：
1. 按条目编号逐条验证，不跳过“数据不足”的条目。
2. 每条输出样本量、核心指标、对照组或基线、证据摘要、结论和建议状态。
3. 结论只能是：数据不足、验证中、倾向支持、倾向反证、已验证待决策。
4. 不允许标记“已采纳”，用户看过后再决策。
5. 不输出候选人姓名、手机号、微信号、完整聊天原文、完整简历正文或完整 URL 参数。
6. 如当前日志字段无法验证某条策略，明确写“缺少什么事实字段/文本分类/后续结果”。
7. 报告最后汇总：
   - 今日可进入用户决策的条目
   - 今日被反证或风险升高的条目
   - 今日数据不足但值得补采字段的条目
   - 明日优先继续观察的条目

更新规则：
- 若证据达到条目判断标准，可把状态建议为“已验证待决策”。
- 若只看到单日方向，不得直接标为已验证，只能标“倾向支持”。
- 若 7 日和 30 日方向相反，优先标“验证中”并说明波动。
- 若样本量不足，标“数据不足”。
```
