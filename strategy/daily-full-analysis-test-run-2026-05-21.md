## 3. 本次能跑出的初步结论

### BASE-001 BOSS 渠道应按完整漏斗复盘

- 建议状态：`倾向支持`
- 证据摘要：近 7 天能看到完整漏斗断点：曝光 3324、详情 1746、打招呼成功 202、聊天打开 153、微信采集 5。最大问题不是单纯曝光不足，而是聊天打开后到微信采集的转化很低。
- 详细分析原因：如果只看前段，曝光到详情打开率为 52.53%，说明候选人进入详情页并不是完全没有发生；打招呼成功 202、聊天打开 153，也说明一部分候选人已经进入沟通链路。但最终微信采集只有 5，微信 / 聊天打开只有 3.27%，微信 / 打招呼成功只有 2.48%，断点明显集中在聊天承接和推进阶段。
- 详细分析原因：2026-05-20 的曝光达到 1770，是近 7 天里最高的一天，但当天微信采集为 0。这说明“曝光增加”本身不能保证最终结果，必须同时看详情、打招呼、聊天打开和微信采集，否则容易把问题误判为单纯流量不足。
- 详细分析原因：日级数据也能看到波动链路：2026-05-18 曝光 583、微信 3；2026-05-19 曝光 967、微信 2；2026-05-20 曝光 1770、微信 0。这个方向支持“按完整漏斗复盘”的底层认知，因为单点指标无法解释结果变化。
- 可能误判点：当前只有分钟汇总，没有候选人级链路；`聊天打开 / 打招呼成功` 在部分时段会超过 100%，可能是历史聊天延迟打开、重复打开或跨分钟归因造成的。因此这条只能判 `倾向支持`，不能直接标记 `已验证待决策`。
- 人工判断点：后续复盘应优先把“微信 / 聊天打开”作为关键漏斗，而不是只盯曝光量或打招呼量。

- 岗位标题、薪资、保底、小白表达、关键词、岗位图片等内容策略。

- 面试、到场、入会、后续有效推进等后链路策略。

这些条目不应该在当前任务里被强行验证，应保持 `数据不足` 或 `验证中`。
