# 事实投影

## 职责

本模块把原始事件转换成可查询事实表。投影只表达已经发生的事实，不写入候选人质量、员工绩效或话术评分等分析结论。

代码归属：

- `src/boss_analysis/domain/`
- `src/boss_analysis/storage/`
- `src/boss_analysis/workers/` 中的重放或批处理入口
- `tests/` 中的 projector 测试

## 事实类型

第一版建议覆盖：

- 页面会话事实：进入、离开、切换和停留。
- 职位上下文事实：职位识别和职位变化。
- 候选人曝光事实：列表曝光和卡片曝光。
- 候选人详情事实：详情打开、关闭、停留时长。
- 打招呼事实：点击、成功、失败。
- 聊天补采事实：聊天打开、快照采集、微信信息采集、补采失败。
- 运行链路事实：上传、队列、解析和消费健康状态。

## 候选人身份原则

候选人身份合并必须保守。

- 优先使用插件事件中的稳定候选人 ID。
- `stable_id_source` 为低置信来源时，只能做局部辅助关联。
- `display_name` 不得单独作为唯一身份。
- 跨岗位、跨页面、跨操作员合并需要明确置信字段，不凭猜测合并。

建议维护 `candidate_identities` 表，用于保存身份线索和置信来源，而不是在每个事实表里重复实现合并规则。

## 投影规则

- 每个 projector 只处理自己声明支持的 `event_type`。
- 未支持事件类型跳过，不报错。
- 事实表写入以源事件 ID 幂等。
- 多事件合并事实要保留源事件 ID，例如详情打开和关闭分别保留 `opened_event_id`、`closed_event_id`。
- 不完整事实可以先写入，后续事件到达后回填。

## 敏感字段

聊天正文、联系方式、完整简历正文和完整牛人分析正文默认视为敏感数据。

规则：

- 原始事件按契约保存，但查询 API 默认不返回敏感正文。
- 事实表优先保存结构化摘要、计数、状态和引用 ID。
- 如需保存正文索引或摘要，必须在任务日志中说明采集范围和访问边界。

## 测试要求

必须覆盖：

- 同一曝光事件重复投影。
- 详情 opened 先到、closed 后到。
- closed 先到或缺失 opened 的异常顺序。
- 打招呼成功和失败事件互不覆盖。
- 未知事件类型跳过。
- 低置信候选人身份不强合并。
