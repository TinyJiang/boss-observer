# 分析系统 AI 协作规范

本目录是后端分析系统独立子项目。

## 必读顺序

1. `docs/ai-worklog.md`
2. `README.md`
3. `docs/boundary.md`
4. `docs/overview-design.md`
5. 与任务相关的 `docs/modules/*.md`
6. `../docs/modules/12-log-specification.md`
7. 相关源码和测试

开始实质工作前，必须先在 `docs/ai-worklog.md` 追加任务开始或接手记录。阶段完成、验证失败、发现阻塞和任务完成时，都要追加阶段记录。

## 边界规则

- 不从 `../extension/` import 任何运行时代码。
- 不读取插件 debug 页、popup Profile 或 Chrome storage 作为生产依赖。
- 不把 BOSS DOM 规则、前台探针实现或插件 helper 复制进分析系统。
- 与前台唯一共享的是日志规范契约； `../docs/modules/12-log-specification.md`，但是本系统绝对不允许去修改此文件，只允许读
- 不允许直接修改任意 `analysis-system` 之外的文件，除非获得用户明确授权
- 分析系统接收 CLS 中的日志事实，不对插件下发业务判断或采集策略。
- 父项目文档只作为契约和背景参考；分析系统的模块设计和进度日志放在本目录 `docs/` 下独立维护。

## CLS Search 接口强约束

- 正式环境严禁使用腾讯云 CLS Search/SearchLog 接口作为数据源，包括但不限于正式 API、worker、定时任务、部署脚本、数据同步任务和面向业务大盘的运行链路。
- `summary` 的本地 SearchLog 验证实现以及任何基于 SearchLog 的 reader 只能用于本地开发、一次性排障和上线前验证；不得写成生产默认值，不得进入生产配置模板，不得作为生产权威数据入口。
- 分钟汇总在正式环境必须来自已批准的生产消费链路，例如 CLS 定时 SQL 的下游同步结果、Kafka/投递链路、数据库表或后续明确设计的非 Search 接口链路；不能为了读取汇总主题而在生产调用 SearchLog。
- 新增或修改代码时，如果某条路径在 `APP_ENV=production` 或正式部署配置下可能触发 Search/SearchLog，必须改成失败关闭或移除该路径；不能用“低频调用”“只读”“临时兜底”作为例外。
- 需要用 Search 接口验证真实 CLS 数据时，必须明确标注为开发/排障动作，不保存为生产状态，不把验证脚本接入正式调度，并在工作日志里记录用途和范围。

## 实现规则

- Python 代码放在 `src/boss_analysis/`。
- 测试放在 `tests/`。
- 配置通过环境变量读取，不写死密钥和云资源凭据。
- 原始事件必须先落库，解析和聚合可以重放。
- 对重复、乱序、迟到、未知事件类型保持兼容。
- 聊天正文、联系方式和完整简历正文默认按敏感数据处理。

## 验证规则

- 行为变化要补测试。
- 数据解析逻辑优先用离线样本测试，不依赖真实 CLS。
- 需要真实云资源时，先在任务说明中写清要操作的资源和风险，得到明确确认后再执行。
