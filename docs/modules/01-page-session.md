# 页面会话模块详细设计

## 1. 模块定位

页面会话模块用于记录招聘专员是否进入 BOSS 直聘工作场景，以及页面在浏览器中的生命周期变化。

该模块不关心具体候选人行为，只负责提供全局会话上下文，帮助后续分析判断招聘专员的工作时段、页面停留和插件运行状态。

## 2. 核心目标

- 识别招聘专员进入和离开 BOSS 工作页面的时间。
- 记录页面切换和页面停留情况。
- 为候选人列表、详情、打招呼、聊天等模块提供会话上下文。
- 记录插件运行异常，便于排查日志缺失原因。

## 3. 需要记录的日志

### 3.1 插件启动日志

记录 Chrome 插件在 BOSS 页面中完成初始化。

用于判断插件是否正常注入页面。

### 3.2 进入 BOSS 页面日志

记录招聘专员进入 BOSS 直聘相关页面。

用于判断工作会话开始。

### 3.3 离开 BOSS 页面日志

记录招聘专员离开 BOSS 页面、关闭标签页或跳转到非 BOSS 页面。

用于判断工作会话结束或中断。

### 3.4 页面切换日志

记录 BOSS 单页应用内部的 URL、路由或页面类型变化。

用于区分推荐列表、候选人详情、聊天、职位管理等不同工作场景。

### 3.5 页面停留日志

记录招聘专员在某类页面上的停留情况。

该日志只记录停留事实，不判断停留是否有效。

### 3.6 插件异常日志

记录插件初始化失败、页面识别失败、日志写入失败、上传链路异常等运行问题。

用于排查采集链路稳定性。

## 4. 触发时机

- 插件 content script 完成初始化时记录插件启动日志。
- 页面 URL 或路由变化时记录页面切换日志。
- 页面进入 BOSS 域名时记录进入 BOSS 页面日志。
- 页面离开 BOSS 域名或标签页关闭前记录离开 BOSS 页面日志。
- 页面停留达到一定时间或页面离开时记录页面停留日志。
- 捕获到插件运行异常时记录插件异常日志。

## 5. 输出给其他模块的上下文

页面会话模块需要为其他日志提供基础上下文：

- 当前会话
- 当前页面类型
- 当前页面 URL
- 插件版本
- 采集时间

这些上下文只用于后续关联和分析，不在插件端做行为判断。

当前正式事件 payload 只保留页面生命周期事实本身：路由切换来源、前后页面 URL/类型、停留时长、离开前页面以及异常 message。完整页面分类对象和页面标题已经在事件根部 `context` 中体现，不再重复写入 payload。

## 6. MVP 范围

MVP 需要完成：

- 识别 BOSS 页面进入和离开。
- 识别页面切换。
- 记录插件启动和异常。
- 将页面会话上下文附加到其他模块日志中。

## 7. 真机验证点

- BOSS 页面是否是单页应用路由切换。
- 推荐页、候选人详情、聊天页是否能通过 URL 或 DOM 稳定识别。
- 标签页关闭或刷新时是否能可靠记录会话结束。
