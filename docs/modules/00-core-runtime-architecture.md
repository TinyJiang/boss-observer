# 核心运行架构详细设计

## 1. 模块定位

核心运行架构描述 Chrome 插件如何启动、如何判断是否启用、如何加载日志探针、如何缓存日志、如何上报日志，以及如何保障采集链路稳定。

该文档不描述具体业务日志内容。候选人列表、候选人详情、打招呼、聊天等具体日志由各自模块文档定义。

## 2. 总体结构

Chrome 插件运行时分为五层：

```text
启动与启用规则
        ↓
页面识别与上下文管理
        ↓
日志探针层
        ↓
本地事件队列
        ↓
日志系统上报
```

各层职责：

- 启动与启用规则：判断插件是否应该在当前页面运行。
- 页面识别与上下文管理：维护当前页面、职位、筛选、招聘专员等上下文。
- 日志探针层：负责观察页面事实并产生独立日志。
- 本地事件队列：负责可靠缓存日志。
- 日志系统上报：负责批量上传、重试和状态记录。

## 3. 插件运行组件

### 3.1 Content Runtime

Content Runtime 运行在 BOSS 页面中，是业务日志采集的主要执行环境。

职责：

- 执行页面启动检查。
- 初始化页面上下文。
- 加载和管理日志探针。
- 接收探针产生的日志。
- 将日志写入本地队列。
- 监听页面路由、DOM 和页面生命周期变化。

### 3.2 Background Runtime

Background Runtime 负责插件级别的后台能力。

职责：

- 管理插件全局配置。
- 管理身份和设备信息。
- 管理上传调度。
- 执行批量上报。
- 处理上传失败和重试。
- 记录插件级运行状态。

Chrome 插件后台运行环境可能会被浏览器挂起，因此后台逻辑不能依赖长期常驻内存。需要将关键状态持久化到本地存储。

### 3.3 Probe Manager

Probe Manager 是日志探针管理器。

职责：

- 根据当前页面类型加载对应探针。
- 控制探针启动、暂停、恢复、停止。
- 隔离单个探针异常，避免影响其他探针。
- 收集探针健康状态。
- 在页面变化后重新评估探针启用状态。

### 3.4 Event Collector

Event Collector 是日志收集器。

职责：

- 接收所有探针产生的日志。
- 补充通用上下文。
- 生成统一事件。
- 写入本地队列。

Event Collector 不做业务分析，不判断事件之间的漏斗关系。

### 3.5 Upload Scheduler

Upload Scheduler 是上传调度器。

职责：

- 决定何时上传。
- 控制上传批次大小。
- 控制上传频率。
- 管理失败重试。
- 在网络恢复、页面关闭、队列达到阈值时触发上传。

## 4. 启动流程

### 4.1 插件安装或更新

插件安装或更新后，需要初始化基础配置：

- 插件版本
- 设备标识
- 默认日志系统地址
- 默认上传频率
- 默认队列容量
- 默认探针开关

### 4.2 BOSS 页面加载

当浏览器打开 BOSS 直聘相关页面时，插件执行启动流程：

```text
页面匹配 BOSS 域名
        ↓
Content Runtime 初始化
        ↓
读取本地配置
        ↓
识别招聘专员身份和页面上下文
        ↓
注册基础监听器
        ↓
启动 Probe Manager
        ↓
加载当前页面适用的探针
        ↓
探针开始产生日志
```

### 4.3 页面内部切换

BOSS 直聘可能是单页应用，页面内部切换不一定触发完整刷新。

插件需要在以下情况重新评估页面状态：

- URL 变化
- 路由变化
- 主要 DOM 区域变化
- 候选人列表刷新
- 候选人详情打开或关闭
- 聊天会话切换

页面变化后，Probe Manager 需要判断当前应该启用哪些探针。

## 5. 启用规则

### 5.1 域名规则

插件只在 BOSS 直聘相关域名运行。

域名匹配规则在实现时通过插件配置控制，并保持最小授权范围。

### 5.2 页面规则

插件需要识别当前页面是否属于招聘工作场景。

典型页面包括：

- 候选人推荐或列表页
- 候选人详情页
- 职位相关页面
- 聊天页面

页面无法识别时，可以记录页面识别异常，但不启动强依赖页面结构的业务探针。

### 5.3 身份规则

日志需要能归属到招聘专员、设备和企业。

身份识别可以来自：

- 插件本地绑定信息
- 登录后的页面信息
- 外部配置
- 日志系统下发配置

身份未完全识别时，可以先记录设备级日志；是否允许记录业务日志由配置决定。

### 5.4 配置规则

所有探针应支持配置化启用。

配置可以控制：

- 插件总开关
- 单个探针开关
- 上传频率
- 上传批次大小
- 本地队列上限
- 聊天快照开关
- 调试日志开关

### 5.5 页面生命周期规则

当前实现暂不使用 `document.visibilityState` 作为采集或上传控制条件，避免产生低价值日志噪音。

建议规则：

- 页面路由变化时，重新识别页面状态并评估探针。
- 页面即将关闭时，尽量触发一次队列 flush。
- 定时扫描和观察器必须有明确间隔与清理逻辑。

## 6. 日志探针设计

### 6.1 探针定义

日志探针是一个独立观察器，负责观察某一类页面事实并产生日志。

探针只做三件事：

- 观察页面事实
- 生成独立事件
- 上报给 Event Collector

探针不做策略判断，不做漏斗计算，不依赖其他探针的事件结果。

### 6.2 探针类型

MVP 需要的探针包括：

- 页面会话探针
- 职位上下文探针
- 筛选探针
- 候选人列表曝光探针
- 候选人详情探针
- 打招呼探针
- 聊天快照验证探针
- 上传链路探针

### 6.3 探针生命周期

每个探针应具备统一生命周期：

```text
registered
        ↓
started
        ↓
paused
        ↓
resumed
        ↓
stopped
```

生命周期说明：

- registered：探针完成注册，但尚未开始观察。
- started：探针开始观察页面。
- paused：页面不可见、页面不匹配或配置关闭时暂停。
- resumed：页面恢复可见或重新匹配后继续观察。
- stopped：页面卸载、插件关闭或探针不再适用。

### 6.4 探针触发方式

探针可以使用多种观察方式：

- 点击事件监听
- 页面可见性监听
- 路由变化监听
- DOM 变化监听
- 元素可见性观察
- 定时快照

不同探针根据业务场景选择合适方式。

候选人列表曝光更适合元素可见性观察；聊天记录更适合会话快照；页面会话更适合生命周期和路由监听。

### 6.5 探针异常隔离

单个探针异常不应影响其他探针。

要求：

- 探针内部异常需要捕获。
- 异常需要记录为插件异常日志。
- 探针异常后可以尝试重启。
- 重启次数过多时暂停该探针。
- 其他探针继续运行。

## 7. 事件处理流程

### 7.1 事件生成

业务探针观察到页面事实后生成独立事件。

事件先进入 Event Collector，再由 Event Collector 补充通用上下文。

### 7.2 上下文补充

通用上下文包括：

- 招聘专员上下文
- 企业上下文
- 设备上下文
- 页面会话上下文
- 当前页面上下文
- 当前职位上下文
- 当前筛选上下文
- 插件版本

具体字段后续设计。

### 7.3 写入本地队列

所有事件都先写入本地队列。

写入成功后，业务探针即可继续运行，不等待网络上传完成。

### 7.4 批量上传

Upload Scheduler 从本地队列读取待上传事件，批量发送到日志系统。

上传成功后，标记对应事件为已上传或从队列中删除。

上传失败时，保留事件并等待重试。

## 8. 本地存储设计

### 8.1 存储分层

本地存储分为三类：

- 内存状态：保存当前页面短期状态。
- 持久化配置：保存插件配置、身份绑定、设备标识。
- 持久化队列：保存待上传日志。

### 8.2 内存状态

用于保存当前页面运行状态：

- 当前页面类型
- 当前职位上下文
- 当前筛选上下文
- 当前已启动探针
- 短期防抖状态

内存状态可以在页面刷新后丢失，不作为可靠存储。

### 8.3 持久化配置

用于保存插件运行配置：

- 插件总开关
- 探针开关
- 招聘专员绑定信息
- 设备标识
- 日志系统地址
- 上传参数

配置变化后，需要通知 Content Runtime 重新评估探针状态。

### 8.4 持久化队列

用于保存待上传日志。

要求：

- 支持追加写入。
- 支持按批次读取。
- 支持上传成功后删除或标记。
- 支持失败重试计数。
- 支持容量上限。
- 支持过期清理。

队列实现优先选择浏览器内适合结构化数据和批量读写的存储能力。

## 9. 上报策略

### 9.1 上传触发条件

上传由以下条件触发：

- 队列达到数量阈值。
- 距离上次上传达到时间阈值。
- 页面即将关闭或刷新。
- 网络从不可用恢复可用。
- 手动调试触发。

### 9.2 上传频率

MVP 建议采用“低延迟 + 低打扰”的批量上报策略：

- 常规事件按固定间隔批量上传。
- 队列积压达到阈值时立即上传。
- 页面关闭前尝试上报一次。
- 上传失败后使用退避重试。

具体时间间隔和批量大小在真机测试后确定。

### 9.3 上传批次

一次上传包含一批待上传事件。

批次需要包含：

- 批次标识
- 插件版本
- 设备信息
- 招聘专员信息
- 事件列表

具体协议由日志系统接入方式决定。

### 9.4 失败重试

上传失败后需要保留事件。

重试原则：

- 网络错误可以重试。
- 日志系统限流需要延迟重试。
- 鉴权失败需要刷新配置或暂停上传。
- 单条格式错误需要隔离，避免阻塞整批日志。

### 9.5 队列清理

队列清理规则：

- 已成功上传的事件可以删除。
- 超过保留期限的事件可以丢弃并记录丢弃日志。
- 队列超过容量上限时，根据策略丢弃旧日志或低优先级日志。

MVP 优先保证核心业务日志，上传链路日志和调试日志可以较低优先级处理。

## 10. 性能与安全边界

### 10.1 性能原则

插件不应明显影响 BOSS 页面使用。

要求：

- 避免高频全量 DOM 扫描。
- 优先使用事件驱动和增量观察。
- 定时任务需要有明确间隔。
- 大量日志写入需要批量化。

### 10.2 页面侵入边界

插件应以观察为主。

要求：

- 不修改 BOSS 页面业务数据。
- 不自动点击或自动发送消息。
- 不阻塞招聘专员正常操作。
- 不依赖会改变页面行为的注入逻辑。

### 10.3 隐私边界

聊天记录、候选人信息、联系方式等可能包含敏感数据。

要求：

- 采集范围通过配置控制。
- 聊天原文采集需要单独确认。
- 可以支持脱敏文本或仅元数据模式。
- 日志系统需要有访问控制和导出控制。

## 11. MVP 范围

核心运行架构 MVP 需要完成：

- 插件只在 BOSS 相关页面启动。
- 支持基础启动流程。
- 支持页面路由变化后重新评估探针。
- 支持探针注册、启动、暂停、恢复、停止。
- 支持探针异常隔离。
- 所有事件先写入本地队列。
- 支持固定间隔批量上传。
- 支持队列达到阈值后立即上传。
- 支持上传失败重试。
- 支持页面关闭前尝试 flush。
- 支持基础配置开关。

## 12. 真机验证点

- BOSS 页面路由切换方式。
- Content Runtime 是否能稳定注入目标页面。
- Background Runtime 挂起后上传调度是否可靠。
- 页面关闭前 flush 的可靠性。
- 本地队列容量是否满足一天工作量。
- 高频候选人曝光日志是否影响页面性能。
- 日志系统批量写入能力和限流规则。
- 探针异常是否会影响页面使用。
