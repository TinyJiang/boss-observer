# 后续分析消费模块详细设计

## 1. 模块定位

后续分析消费模块用于消费日志系统导出的数据，支撑策略分析和员工监督。

该模块当前不作为产品功能实现，但需要在设计上明确未来会如何使用日志，避免插件采集阶段遗漏关键数据。

## 2. 核心目标

- 基于独立事实日志还原招聘专员的候选人筛选路径。
- 分析候选人从列表曝光到详情打开、打招呼、回复、转化的漏斗。
- 分析不同筛选策略和打招呼策略的效果。
- 分析员工工作量、工作质量和异常行为。
- 分析回复速度、聊天质量和话术转化率。

## 3. 主要分析方向

### 3.1 曝光到打开详情漏斗

分析招聘专员在看到候选人后，选择打开详情的比例和特征。

用于评估候选人初筛能力。

### 3.2 打开详情到打招呼漏斗

分析招聘专员打开详情后，选择打招呼的比例和特征。

用于评估详情判断和触达决策。

### 3.3 打招呼到候选人回复漏斗

分析哪些打招呼行为能带来候选人回复。

用于评估触达质量和候选人匹配度。

### 3.4 候选人筛选能力

综合分析曝光、打开详情、打招呼、回复之间的关系。

用于识别哪些招聘专员更擅长从候选人列表中挑出高潜候选人。

### 3.5 招聘专员工作量

分析招聘专员的页面活跃、候选人浏览、详情打开、打招呼和沟通行为。

用于判断实际工作投入。

### 3.6 招聘专员工作质量

分析工作量与回复、沟通、转化之间的关系。

用于区分有效工作和低质量批量操作。

### 3.7 回复速度

分析候选人发来消息后，招聘专员的首响时间和平均回复间隔。

该方向依赖聊天记录模块提供可靠消息时间线。

### 3.8 聊天质量

分析招聘专员使用的话术、消息长度、消息轮次、候选人响应和后续转化。

该方向依赖聊天记录模块提供消息内容或脱敏文本。

### 3.9 话术转化率

分析不同首句、不同沟通策略和不同候选人类型之间的转化差异。

## 4. 对采集侧的数据要求

后续分析消费模块依赖采集侧提供：

- 独立事件日志
- 稳定时间戳
- 招聘专员上下文
- 职位上下文
- 筛选上下文
- 候选人可关联标识
- 页面类型
- 事件类型
- 聊天会话或消息信息

具体字段设计在真机验证后确定。

## 5. MVP 范围

MVP 阶段需要保证日志采集结果能支持后续分析消费。

重点是：

- 核心事件完整。
- 事件时间准确。
- 候选人可以在曝光、详情、打招呼之间被关联。
- 职位和筛选上下文可以随日志导出。
- 聊天记录采集方案经过验证。

## 6. 真机验证点

- 候选人标识是否足以跨模块关联。
- 曝光、详情、打招呼事件之间是否能在导出数据中串起来。
- 职位和筛选上下文是否稳定。
- 聊天快照是否足以计算回复速度。
- 日志量是否适合后续 AI 分析。
