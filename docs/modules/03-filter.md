# 筛选模块详细设计

## 1. 模块定位

筛选模块用于记录招聘专员如何使用候选人筛选条件。

筛选行为是候选人筛选能力分析的重要前置条件。后续可以基于筛选日志分析不同筛选策略对候选人打开率、打招呼率、回复率和转化率的影响。

## 2. 核心目标

- 记录招聘专员打开筛选面板的行为。
- 记录招聘专员确认筛选条件的行为。
- 为候选人列表曝光日志提供筛选上下文。
- 支持后续按筛选组合分析候选人质量和招聘效果。

## 3. 需要记录的日志

### 3.1 筛选面板打开日志

记录招聘专员打开筛选面板。

用于判断招聘专员是否主动使用筛选能力。

### 3.2 筛选确认日志

记录招聘专员确认或应用筛选条件。

用于形成候选人列表曝光时的筛选上下文。

## 4. 触发时机

- 招聘专员点击筛选入口时记录筛选面板打开日志。
- 招聘专员点击确认、应用、搜索等按钮使筛选生效时记录筛选确认日志。
- 筛选生效后，候选人列表模块应使用最新筛选上下文记录候选人曝光。

## 5. 筛选上下文

筛选模块需要维护当前筛选上下文，供候选人列表、详情和打招呼模块使用。

筛选上下文可以包括：

- 活跃状态
- 求职意向
- 年龄范围
- 学历
- 工作经验
- 薪资范围
- 关键词
- 其他 BOSS 页面提供的筛选项

具体字段在真机验证后确定。

## 6. MVP 范围

MVP 需要完成：

- 能记录筛选面板打开。
- 能记录筛选确认。
- 能维护最近一次生效的筛选上下文。
- 能把筛选上下文附加到候选人列表曝光日志中。

## 7. 真机验证点

- 筛选项是否有明确的确认动作。
- 筛选条件变化后候选人列表是否会刷新。
- 筛选条件是否能从 DOM 稳定读取。
- 搜索关键词是否需要脱敏或哈希。
- 多次打开筛选面板但不确认时是否应记录为独立行为。
