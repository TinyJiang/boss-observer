# 筛选模块详细设计

## 1. 模块定位

筛选模块用于记录招聘专员如何使用候选人筛选条件。

筛选行为是候选人筛选能力分析的重要前置条件。后续可以基于筛选日志分析不同筛选策略对候选人打开率、打招呼率、回复率和转化率的影响。

## 2. 核心目标

- 记录招聘专员打开筛选面板的行为。
- 记录招聘专员确认筛选条件的行为。
- 记录最近一次确认筛选时页面中已选筛选项的短摘要。
- 为后续候选人列表曝光日志提供筛选上下文基础。
- 支持后续按筛选组合分析候选人质量和招聘效果。

## 3. 需要记录的日志

### 3.1 筛选面板打开日志

记录招聘专员打开筛选面板。

用于判断招聘专员是否主动使用筛选能力。

当前事件类型：

- `candidate_filter.panel_opened`

### 3.2 筛选确认日志

记录招聘专员确认或应用筛选条件。

用于形成候选人列表曝光时的筛选上下文。

当前事件类型：

- `candidate_filter.applied`

## 4. 触发时机

- 招聘专员在候选人列表页点击短文本的“筛选 / 更多筛选 / 高级筛选 / 过滤”等入口时，记录筛选面板打开日志。
- 招聘专员在可识别为筛选面板的上下文里点击“确定 / 确认 / 应用 / 完成 / 搜索 / 查看结果”等动作时，记录筛选确认日志。
- 普通页面搜索框、非筛选面板中的确认按钮不会记录为筛选确认。

## 5. 筛选上下文

筛选模块第一版在 `FilterProbe` 内维护最近一次确认的筛选摘要，后续可以接入 `SessionContext` 或候选人列表曝光 payload。

当前第一版尚未把筛选上下文附加到候选人列表、详情或打招呼事件。原因是 BOSS 筛选面板 DOM 和真实字段命中率仍需真机验证，先避免把不稳定筛选假设扩散到所有候选人事件。

筛选摘要来自面板中可识别为已选中的短筛选项，可以包括：

- 活跃状态
- 求职意向
- 年龄范围
- 学历
- 工作经验
- 薪资范围
- 关键词
- 其他 BOSS 页面提供的筛选项

当前实现中，`candidate_filter.panel_opened` 只记录面板打开事实，`filter.conditionCount` 固定为 `0`，不从打开瞬间读取筛选摘要，避免误把候选人列表文本当作筛选条件。

`candidate_filter.applied` 只输出 `filter.conditionCount` 和 `filter.conditions`：

- `conditions` 最多保留 12 条。
- 单条条件最长 48 个字符。
- `关键词`、`关键字`、`搜索关键词`、`姓名`、`手机`、`电话`、`微信`、`联系方式` 等自由输入或敏感字段只记录为“已填写”，不保存原值。
- `不限`、`全部`、`请选择`、`确定`、`搜索`、`重置`、`清空` 等默认项或动作文本不进入摘要。
- 摘要优先来自 `aria-selected`、`aria-checked`、`aria-pressed`、`input:checked` 或常见 `selected/active/checked/current` 样式标记的控件；真实 BOSS 面板中只通过 chip 背景色标记已选项时，会按筛选字段行读取有明显选中背景的短选项，并补充可读到的年龄滑块范围。年龄滑块除普通文本和 `aria` / `data` / `value` 属性外，也会读取年龄行内滑块元素的 `::before` / `::after` 文本内容，因为真实页面可能用 CSS 伪元素渲染数值。
- 如果真实页面没有可识别选中态，宁可输出 `conditionCount: 0`，也不把面板所有可见候选项当作已选条件。

## 6. MVP 范围

第一版已完成：

- 能记录筛选面板打开。
- 能记录筛选确认。
- 能在探针内维护最近一次生效的筛选摘要。
- 能把确认事件与最近一次打开事件通过 `openedEventId` 关联。

暂未完成：

- 暂未把筛选上下文附加到候选人列表曝光日志中。
- 暂未定义稳定的结构化筛选字段枚举。
- 暂未确认真实 BOSS 页面所有筛选项 DOM 结构。

## 7. 真机验证点

- 筛选项是否有明确的确认动作。
- 筛选条件变化后候选人列表是否会刷新。
- 筛选条件是否能从 DOM 稳定读取。
- 搜索关键词是否需要脱敏或哈希。
- 多次打开筛选面板但不确认时是否应记录为独立行为。
- `candidate_filter.applied` 的 `conditions` 是否覆盖真实已选条件，是否遗漏城市、职位、薪资等关键筛选项。
