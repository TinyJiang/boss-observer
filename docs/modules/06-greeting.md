# 打招呼模块详细设计

## 1. 模块定位

打招呼模块用于记录招聘专员对哪些候选人发起了打招呼行为。

这是 MVP 的核心模块之一。打招呼日志是候选人筛选链路中的关键结果事件，后续可与卡片曝光、详情打开、候选人回复等日志关联分析。

## 2. 核心目标

- 记录招聘专员点击打招呼按钮。
- 记录打招呼成功。
- 记录打招呼失败。
- 将候选人、职位、筛选、页面会话上下文附加到打招呼日志中。

## 3. 需要记录的日志

### 3.1 打招呼按钮点击日志

记录招聘专员点击打招呼按钮。

用于判断招聘专员发起触达意图。

当前事件类型为 `candidate_greeting.clicked`。

### 3.2 打招呼成功日志

记录系统确认打招呼成功。

用于判断候选人实际被触达。

当前事件类型为 `candidate_greeting.succeeded`。第一版只在页面可观察到成功提示或按钮状态变化时记录成功。

### 3.3 打招呼失败日志

记录打招呼失败或被系统限制。

用于排查打招呼点击和实际触达不一致的问题。

当前事件类型为 `candidate_greeting.failed`。第一版只在页面可观察到失败、限制、频控、网络错误等提示时记录失败；点击后超时但没有可观察结果时，不会把缺少确认误写成失败。

## 4. 触发时机

- 招聘专员点击打招呼按钮时记录按钮点击日志。
- 页面出现成功状态、消息发送成功、按钮状态变化或系统提示时记录打招呼成功日志。
- 页面出现失败提示、系统限制、网络错误或按钮状态未生效时记录打招呼失败日志。

当前实现：

- content script 在顶层页面和同源 iframe 中监听点击事件。
- 只把简短且包含“打招呼”的按钮/链接文本当作打招呼动作，避免把整张候选人卡片误判为按钮。
- 点击按钮后优先从按钮所在候选人卡片读取候选人信息；如果按钮和候选人信息是兄弟节点，则从附近同级候选人信息块补上下文。
- 如果按钮位于已曝光候选人卡片内，或详情页仍能关联到最近打开的已曝光候选人，打招呼点击和后续成功/失败结果会继承同一个 `candidateId`、`exposureKey` 和 `exposedEventId`。
- 如果点击目标只能读到按钮局部文本，打招呼探针会优先按候选人 `candidateId` 回查本地候选人快照；若最近打开的详情候选人仍处于可见/刷新有效期内，则继承该详情候选人的基础 `profile` 和详情摘要，避免为同一候选人生成孤立的按钮文本指纹 ID。详情关闭时会清理这份兜底上下文。
- 点击后建立短时间 pending attempt，随后轮询按钮状态和页面 toast/message/notice/dialog 等提示。
- pending 超时只丢弃等待状态，不发出失败事件。

## 5. 依赖上下文

打招呼日志需要尽量带上：

- 页面会话上下文
- 当前职位上下文
- 当前筛选上下文
- 候选人可识别信息
- 当前页面类型
- 打招呼入口

打招呼入口可以来自候选人列表、候选人详情、聊天窗口或其他 BOSS 页面位置。具体识别方式在真机验证后确定。

当前 payload 会带上：

- `entry`: 当前识别到的入口，常见值为 `candidate_list`、`candidate_detail`、`chat` 或 `unknown`。
- `candidate`: 与候选人列表/详情共用的候选人身份和核心 profile 快照。
- `clickedEventId`: 只在成功/失败结果事件中出现，指向对应的点击事件 ID。
- `greeting.status`: 只在成功/失败结果事件中出现，记录 `succeeded` 或 `failed`。
- `greeting.detectedBy`: 只在成功/失败结果事件中出现，记录结果来自按钮状态还是页面提示。

正式 payload 不再输出 `page`、`sourceUrl`、按钮文案、内部 `targetKey` 或识别用 `matchedSignals`；页面上下文看事件根部 `context`，点击与结果通过事件 ID 和 `clickedEventId` 关联。

当前不会采集打招呼话术、聊天正文、完整简历正文、手机号、微信号等敏感文本。

## 6. MVP 范围

MVP 需要完成：

- 能记录打招呼按钮点击。
- 能区分打招呼成功和失败。
- 能在列表页和详情页中尽量识别候选人上下文。
- 能把打招呼日志可靠写入本地队列并上传。

当前第一版已完成按钮点击和页面可观察结果采集。由于真实 BOSS 交互可能存在确认弹窗、默认话术编辑框、按钮状态延迟或不同页面文案差异，结果事件只表示插件实际观察到的页面事实，不表示业务上最终一定触达成功或失败。

## 7. 真机验证点

- BOSS 是否有不同形态的打招呼按钮。
- 点击按钮后是否会打开确认弹窗或消息编辑框。
- 成功和失败是否有稳定提示。
- 打招呼是否可能自动发送默认话术。
- 列表页直接打招呼和详情页打招呼是否行为不同。
