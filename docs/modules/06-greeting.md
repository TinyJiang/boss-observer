# 打招呼模块详细设计

## 1. 模块定位

打招呼模块用于记录招聘专员对哪些候选人发起了打招呼行为。

这是 MVP 的核心模块之一。打招呼日志是候选人筛选链路中的关键结果事件，后续可与列表曝光、详情打开、候选人回复等日志关联分析。

## 2. 核心目标

- 记录招聘专员点击打招呼按钮。
- 记录打招呼成功。
- 记录打招呼失败。
- 将候选人、职位、筛选、页面会话上下文附加到打招呼日志中。

## 3. 需要记录的日志

### 3.1 打招呼按钮点击日志

记录招聘专员点击打招呼按钮。

用于判断招聘专员发起触达意图。

### 3.2 打招呼成功日志

记录系统确认打招呼成功。

用于判断候选人实际被触达。

### 3.3 打招呼失败日志

记录打招呼失败或被系统限制。

用于排查打招呼点击和实际触达不一致的问题。

## 4. 触发时机

- 招聘专员点击打招呼按钮时记录按钮点击日志。
- 页面出现成功状态、消息发送成功、按钮状态变化或系统提示时记录打招呼成功日志。
- 页面出现失败提示、系统限制、网络错误或按钮状态未生效时记录打招呼失败日志。

## 5. 依赖上下文

打招呼日志需要尽量带上：

- 页面会话上下文
- 当前职位上下文
- 当前筛选上下文
- 候选人可识别信息
- 当前页面类型
- 打招呼入口

打招呼入口可以来自候选人列表、候选人详情、聊天窗口或其他 BOSS 页面位置。具体识别方式在真机验证后确定。

## 6. MVP 范围

MVP 需要完成：

- 能记录打招呼按钮点击。
- 能区分打招呼成功和失败。
- 能在列表页和详情页中尽量识别候选人上下文。
- 能把打招呼日志可靠写入本地队列并上传。

## 7. 真机验证点

- BOSS 是否有不同形态的打招呼按钮。
- 点击按钮后是否会打开确认弹窗或消息编辑框。
- 成功和失败是否有稳定提示。
- 打招呼是否可能自动发送默认话术。
- 列表页直接打招呼和详情页打招呼是否行为不同。
