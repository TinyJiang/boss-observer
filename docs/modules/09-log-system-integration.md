# 日志系统对接模块详细设计

## 1. 模块定位

日志系统对接模块用于将 Chrome 插件采集到的日志上报到成熟日志系统。

本项目第一阶段不单独建设复杂后端日志服务，优先复用成熟日志系统的接收、保存、查询和导出能力。

## 2. 核心目标

- 接收 Chrome 插件批量上传的日志。
- 保存原始事实日志。
- 支持后续按日期、招聘专员、岗位、事件类型查询。
- 支持导出数据给 AI 或独立分析系统。
- 保留足够原始信息，避免过早加工导致后续分析受限。

## 3. 接入边界

Chrome 插件负责：

- 生成事实日志。
- 本地缓存日志。
- 批量上传日志。
- 记录上传成功、失败和重试。

日志系统负责：

- 接收日志。
- 保存日志。
- 查询日志。
- 导出日志。
- 提供基础检索能力。

## 4. 日志分类

日志系统需要接收以下类型的日志：

- 页面会话日志
- 职位日志
- 筛选日志
- 候选人列表日志
- 候选人详情日志
- 打招呼日志
- 聊天记录日志或聊天快照日志
- 本地队列与上传链路日志
- 插件异常日志

## 5. 查询维度

日志系统需要支持以下查询维度：

- 日期
- 招聘专员
- 岗位
- 候选人
- 事件类型
- 页面类型
- 上传批次
- 插件版本

具体索引和字段设计依赖选型后的日志系统能力。

## 6. 导出方向

导出的数据主要服务于后续分析：

- 招聘行为漏斗分析
- 候选人筛选能力分析
- 员工工作监督
- 回复速度分析
- 聊天质量分析
- 话术转化率分析

导出格式优先考虑日志系统原生支持的 JSON 或 CSV。

## 7. MVP 范围

MVP 需要完成：

- 插件日志可以成功上报到日志系统。
- 日志系统能保存原始日志。
- 能按日期查询日志。
- 能按招聘专员查询日志。
- 能按岗位查询日志。
- 能按事件类型查询日志。
- 能导出日志。

## 8. 真机验证点

- 选定日志系统的写入限制。
- 单次批量上传大小限制。
- 查询和导出能力是否满足分析需求。
- 是否支持去重或需要分析侧自行去重。
- 日志保留周期。
- 敏感数据存储和访问控制能力。
